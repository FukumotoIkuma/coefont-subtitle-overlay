# CoeFont Subtitle Overlay

CoeFont通訳の字幕を、全画面スライドショーの上に重ねて聴衆に見せる単一HTML。
ビルドなし・インストールなし・サーバー処理なし。発表ソフト側の設定は何も変えない(発表者ツールもそのまま使える)。

## 起動

Chrome / Edge で次のURLを開くだけ:

https://fukumotoikuma.github.io/coefont-subtitle-overlay/

`main` ブランチがそのまま GitHub Pages で配信される。配信は10分キャッシュされるので、画面右下の「配信日時」で読み込んでいる版を確認できる。

## 仕組み

- **字幕**: CoeFont の招待URLをページ内に iframe で埋め込み、字幕の範囲だけを CSS で切り抜く。画面共有は使わない
- **スライド**: スライドショーのウィンドウを画面共有で取り込み、下地として全面に映す
- **出力**: この2つを別窓の「出力ウィンドウ」の中で重ね、聴衆側ディスプレイで全画面表示する。スライドショーの上にかぶさる形になる
- **操作**: 位置・範囲・透過は手元のタブから調整し、全画面中の出力ウィンドウへ即時反映される

同じ文書内の合成なので、字幕の背景を抜く(透過)、位置と大きさを固定する、が CSS だけでできる。

### CoeFont をタブ共有で取り込まない理由

Chrome はタブを共有している間、同じプロファイルの全ウィンドウの全タブに「〜を共有しています」バーを出す(Chromium の `TabSharingUIViews::CreateInfobarsForAllTabs`)。全画面にしても消えず、ページ側から消す手段もない。例外は PiP の窓だけ。
ウィンドウの共有はこの対象外(同 `desktop_capture_devices_util.cc`)なので、スライドは「ウィンドウ」として取り込む。

## 使い方

画面は1つ。上のプレビューが聴衆に見える構図(スライド+字幕の位置)で、下に「ソース」「字幕の見た目」「出力」が並ぶ。

1. 「ソース」に CoeFont の招待URLを貼って「読み込む」。出力が別のウィンドウ(ブラウザの状態によってはタブ)で開く
2. 出力側に CoeFont の画面がそのまま出るので、開始ボタンを押し、必要な設定(文字サイズ、Single / All など)を済ませる
3. 発表ソフトでスライドショーを通常どおり開始する(聴衆側に全画面、手元に発表者ツール)
4. 「スライドショーのウィンドウ」の「選択」で、選択画面の**ウィンドウ**からスライドショーを選ぶ(タブや画面全体は選ばない)
5. プレビューの字幕の枠を直接つかんで調整する
   - 中をドラッグ: 移動
   - 赤い角: 拡大縮小
   - 青い辺: 切り抜き(初期状態は切り抜きなし。字幕以外を切り落とす)
6. 出力を聴衆側ディスプレイへ移し(タブで開いた場合はウィンドウから切り離す)、その中の「全画面にする」を押す
7. 手元の発表者ツールをクリックして操作を発表ソフトへ戻す

調整はすべて、出力が全画面のままでも即時に反映される。

- CoeFont の実物は出力側にだけ表示する(招待URLを開くのは1か所)。手元のプレビューでは、同じ位置・大きさの縞模様の枠で示す
- 切り抜いたあとで CoeFont 自体の設定を変えたいときは、「出力側: CoeFont の画面全体を表示」で出力を一時的に全体表示にする。全画面にするときは自動で字幕表示に戻る
- 配置・切り抜き・見た目は localStorage に保存され、次回復元される。招待URLはタブを閉じるまでだけ保持する
- 別のタブでも同じ招待URLを開いていると音声が二重に鳴るので、そちらは閉じる
- 出力を閉じて開き直すと CoeFont は読み込み直しになる。本ツールのタブを閉じると出力も閉じる

## 配置

「レイアウトと字幕」の「配置」で切り替える。

| 配置 | スライド | 字幕 |
|---|---|---|
| スライドに重ねる | 画面いっぱい | 好きな位置・大きさでスライドの上に重ねる。透過・不透明度が使える |
| スライドの下に並べる | 境界線より上に縮めて収める | 境界線より下の領域 |
| スライドの右 / 左に並べる | 境界線の反対側に縮めて収める | 境界線の右 / 左の領域 |

並べる配置では、プレビューの赤い境界線をドラッグ(または「字幕の領域の高さ / 幅」)でスライドと字幕の割合を変える。字幕は、領域に収まる大きさで中央に置かれる。

## 3つの別々の設定

字幕の見え方は次の3つで決まり、互いに影響しない。アプリがどれかを勝手に変えることはない。

| 設定 | 何を決めるか | 操作 |
|---|---|---|
| 境界線 | スライドと字幕の領域の割合 | 赤い境界線をドラッグ |
| CoeFont の窓の形 | CoeFont を描く窓の幅と高さ(px)。幅を狭くするほど文字が大きく映り、高さを増やすほど行数が増える | 「CoeFont の窓の幅」「CoeFont の窓の高さ」 |
| 切り抜き | 窓のうち、どこを見せるか | 字幕の枠の青い辺をドラッグ |

- 初期状態は、窓が 960×540px、切り抜きなし。操作部(文字サイズ、Single / All、言語)に触れる状態から始め、設定が済んだら字幕以外を切り落とす
- 字幕の領域と、切り抜いた範囲の縦横比が合わない分は黒い余白になる。「窓の形を字幕の領域に合わせる」を押すと、切り抜きはそのままで、余白が出ない高さへ窓を変える(押したときだけ)。左右に並べる配置で窓を縦長にしたいときに使う。出力を開いていれば出力側の今の画面の形に、開いていなければプレビューの形に合わせる。出力を全画面にするなどして画面の形が変わると合わなくなるが、自動では合わせ直さず、ボタンの下に「余白があります」と出し続けるので、そのときにもう一度押す
- 参考: CoeFont の視聴画面は、上端から約118pxがロゴ・文字サイズ・言語切替で、その下が左右いっぱいの字幕欄(幅 560〜1280px で実測)
- 切り抜きは四辺からの余白(px)で持っているので、窓の形を変えても切った位置はずれない。窓は、切り抜いた残りが 40px を下回る大きさには縮められない(切り抜きのほうを詰めることはしない。止まったときは理由を表示する)
- 初期化も別々: 「切り抜きを初期化」は切り抜きだけ、「窓の形を初期化」は窓の幅と高さだけ、「配置を初期化」は重ねる配置での位置と大きさだけを戻す
- 並べる配置で切り抜きの辺をつかんでいる間は、枠を収め直さず、つかんだ辺だけが動く。離したときに新しい切り抜きで領域に収め直す

## 字幕だけの小窓版

[pip.html](https://fukumotoikuma.github.io/coefont-subtitle-overlay/pip.html) は、CoeFont のタブを共有して字幕だけを常に最前面の小窓(PiP)に出す版。透過はできないが、全画面のスライドショーより手前に通常版を出せない環境でも表示できる。

## 対応環境

デスクトップ版 Chrome / Edge。小窓版は Chrome / Edge 専用。

## 未検証・既知の制約

- **重なり順**: 発表ソフトを操作したときにスライドショーが本ツールの全画面より手前に出てくる環境では、字幕が隠れる(スライド自体は見える)。出力ウィンドウは通常の窓なので「常に最前面」にはできない。本番機で必ず事前確認すること。駄目な場合は小窓版を使う
- **隠れたスライドショーの取り込み**: 本ツールの全画面の下に隠れた状態でも、スライド送りやアニメーションが映り続けるかは OS と発表ソフトに依存する
- **出力側での CoeFont の開始操作**: スライドを取り込む前なら、字幕の枠内の開始ボタンが効くことを確認済み。自動操作での検証では、スライドを先に取り込んだ状態だとクリックが CoeFont に届かなかった(実際のマウス操作でも起きるかは未確認)。届かない場合は、スライドを一度「停止」してから開始する
- **実際の招待URLでの動作**: 実際の招待URLが iframe 内で開き、開始画面が表示され、スライドに透過合成できることは確認済み。発話中に字幕が流れて自動スクロールする様子は未確認
- スライドは映像経由になるため、わずかな遅延と画質低下がある
- ウィンドウ共有中は「画面を共有しています」という浮きバーが出ることがある。「非表示」で消せる
